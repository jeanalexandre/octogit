# Spec : Gérer les branches

> Produit par `/spec` à partir de `brief.md`. Fichier : `specs/gerer-les-branches.md`. Validé par l'humain le 07/11/2026.
> Révisions : aucune.

## Objectif
Depuis `History`, je change de tâche en changeant de branche : double-clic, sélecteur de la `Toolbar` ou clic droit › Checkout, y compris sur une `origin/…` jamais récupérée. Je crée une branche depuis la courante ou depuis un commit, en tapant son nom en ligne. Je renomme ou supprime une branche locale, et je supprime une branche sur `origin`. Je ne me retrouve jamais en HEAD détachée, et je navigue entre mes travaux sans terminal.
- Jobs servis : J-16

## Périmètre
- **Inclus :** checkout par double-clic (`BranchSidebar`, `RefLabel`), par le sélecteur filtrable de la `Toolbar` et par clic droit › Checkout ; création de la branche locale qui suit une `origin/…` non récupérée ; confirmation quand la branche locale de même nom diffère ; modifications non commitées gardées si compatibles, sinon refus ; Branch (`Toolbar`) et « Create branch here » (`RefContextMenu` d'un commit, `CommitDetail`), avec saisie en ligne du nom ; Checkout de `CommitDetail` (repris de `specs/revenir-en-arriere.md`, renvoi « gérer les branches (checkout, Branch here) ») ; Rename ; « Delete local » ; « Delete from origin », bloqué comme Push par une identité non conforme ; entrées désactivées pendant une opération en cours ; erreurs de Git.
- **Exclu :**
  - Suppression en lot des branches fusionnées, renommage d'une branche sur `origin`, comparaison de deux branches, stash automatique au checkout, épinglage ou masquage de branches (non-objectifs).
  - HEAD détachée : aucun geste d'Octogit n'y mène.
  - Bandeau et fin d'une opération en cours (`OperationBanner`, Continue, Abort) → `specs/resoudre-les-conflits.md`
  - Contrôle de conformité de l'identité et « Fix repository identity » → `specs/proteger-l-identite.md`
  - Checkout de la branche qui reçoit avant un merge ou un rebase → `specs/integrer-une-branche.md` (CA-5)
  - Publication d'une branche « Not published » → `specs/synchroniser.md` (CA-13, CA-14) ; indicateur « Not published » → `specs/explorer-l-historique.md` (CA-11)
  - Disparition d'une `origin/…` supprimée par un autre clone, au Fetch All → `specs/synchroniser.md` (CA-3)

## Critères d'acceptation
- **CA-1** : Étant donné `develop` courante et un arbre de travail propre, quand je double-clique sur `feature/profiles` dans `BranchSidebar` ou sur sa `RefLabel`, alors `feature/profiles` devient courante (`git branch --show-current`), l'arbre de travail est identique à son sommet, et le graphe la montre courante sans changer d'écran.
- **CA-2** : Étant donné le sélecteur de branche de la `Toolbar` ouvert, quand je tape `graph`, alors la liste ne montre que `feature/graph` et `origin/feature/graph` parmi les branches du dépôt ; quand j'en choisis une, alors le checkout a lieu comme en CA-1 ou CA-4.
- **CA-3** : Étant donné un clic droit sur une branche locale ou une `origin/…`, alors le `RefContextMenu` propose Checkout, qui agit comme le double-clic.
- **CA-4** : Étant donné `origin/feature/graph` sans branche locale `feature/graph`, quand je fais son checkout par l'un des trois gestes, alors `feature/graph` est créée sur le même commit, suit `origin/feature/graph` (`git rev-parse --abbrev-ref feature/graph@{upstream}`), devient courante, et l'indicateur d'avance / retard affiche 0 / 0. Étant donné une `feature/graph` locale sur le même commit que `origin/feature/graph`, alors son checkout a lieu sans confirmation, sans créer ni déplacer de branche.
- **CA-5** : Étant donné un fichier modifié, indexé ou non, identique sur les deux branches, quand je fais un checkout, alors il a lieu et le fichier garde ses modifications et son état d'indexation (`git status`).
- **CA-6** : Étant donné des modifications non commitées qu'un checkout écraserait, quand je le lance par n'importe quel geste, y compris via « Create branch here », alors il est refusé avec « Commit or stash your changes before switching branches. » ; aucune branche n'est créée ni déplacée, la branche courante, l'index et l'arbre de travail ne changent pas.
- **CA-7** : Étant donné `CommitDetail` d'un commit qui porte une seule branche locale, `feature/profiles`, quand je clique sur Checkout, alors `feature/profiles` devient courante comme en CA-1. Étant donné un commit qui porte `feature/profiles` et `fix/graph`, alors Checkout ouvre un menu qui liste ces deux branches, et le checkout n'a lieu qu'après mon choix. Étant donné un commit qui ne porte qu'une `origin/…`, alors Checkout agit comme le checkout de cette `origin/…` (CA-4, CA-21). Étant donné un commit qui ne porte aucune branche, alors Checkout n'est pas proposé et « Create branch here » l'est.
- **CA-8** : Étant donné `develop` courante, quand je clique sur Branch dans la `Toolbar`, alors un champ de saisie apparaît à la place de la `RefLabel` du sommet de `develop` ; quand je tape `feature/graph` puis Entrée, alors `feature/graph` est créée sur ce commit, devient courante, ne suit aucune branche distante (« Not published »), et l'arbre de travail est inchangé.
- **CA-9** : Étant donné un clic droit sur le commit `c41d8e0` ou son `CommitDetail`, quand je choisis « Create branch here », tape `fix/graph` puis Entrée, alors `fix/graph` est créée sur `c41d8e0` et devient courante, sans HEAD détachée.
- **CA-10** : Étant donné la saisie en ligne (création ou Rename), quand le nom tapé est déjà celui d'une branche locale (`develop`) ou refusé par Git (`feature graph`, `feature..x`), alors un message d'une ligne le signale avant toute validation, et Entrée ne crée ni ne renomme rien.
- **CA-11** : Étant donné la saisie en ligne ouverte, quand je fais Échap, alors elle se ferme ; aucune branche n'est créée ni renommée et la branche courante ne change pas.
- **CA-12** : Étant donné `feature/graph` qui suit `origin/feature/graph`, quand je choisis Rename dans son menu, tape `feature/lanes` puis Entrée, alors `feature/lanes` existe sur le même commit, `feature/graph` n'existe plus, `feature/lanes` suit toujours `origin/feature/graph`, et `origin/feature/graph` existe toujours sur `origin` (`git ls-remote origin`). Étant donné la branche courante renommée, alors elle reste courante.
- **CA-13** : Étant donné le menu de la branche courante, alors « Delete local » est désactivé avec une raison affichée ; aucun raccourci ne le lance.
- **CA-14** : Étant donné `feature/profiles` courante et `feature/graph` dont tous les commits sont dans `feature/profiles`, quand je choisis « Delete local » sur `feature/graph`, alors elle est supprimée sans confirmation ; `origin/feature/graph` est inchangée.
- **CA-15** : Étant donné `feature/graph` non courante, avec 3 commits portés par aucune autre branche locale ou distante, quand je choisis « Delete local », alors une confirmation affiche « feature/graph has 3 commits not merged anywhere. Delete anyway? » sans rien modifier ; quand je confirme, alors elle est supprimée ; quand j'annule ou fais Échap, alors rien ne change.
- **CA-16** : Étant donné `feature/profiles` courante et `feature/graph` dont les commits ne sont pas tous dans `feature/profiles` mais sont tous dans `origin/develop`, quand je choisis « Delete local », alors une confirmation affiche « feature/graph is not merged into feature/profiles (merged into origin/develop). Delete anyway? » sans rien modifier ; confirmer et annuler agissent comme en CA-15.
- **CA-17** : Étant donné un clic droit sur `origin/feature/graph` suivie par la branche locale `feature/graph`, quand je choisis « Delete from origin », alors une confirmation nomme `origin/feature/graph` et `feature/graph` sans rien modifier. Étant donné aucune branche locale qui la suit, alors la confirmation ne nomme que `origin/feature/graph`.
- **CA-18** : Étant donné cette confirmation, quand je confirme, alors `feature/graph` n'existe plus sur `origin` (`git ls-remote origin`), `origin/feature/graph` disparaît du graphe, et aucune branche locale n'est supprimée ni déplacée ; la branche locale `feature/graph` ne suit plus aucune branche distante et affiche « Not published ». Quand j'annule ou fais Échap, alors rien ne change, ni en local ni sur `origin`.
- **CA-19** : Étant donné une identité non conforme ou « No profile », alors « Delete from origin » est refusé avec la même raison que Push (`specs/proteger-l-identite.md`) ; rien ne change sur `origin`. Checkout, Branch, « Create branch here », Rename et « Delete local » restent disponibles.
- **CA-20** : Étant donné un merge, un rebase, un cherry-pick ou un revert en cours, y compris lancé depuis le terminal, alors le checkout (tous gestes), Branch, « Create branch here », Rename, « Delete local » et « Delete from origin » sont désactivés avec la raison « Operation in progress. » ; aucun raccourci ne les lance ; ils redeviennent actifs à la fin de l'opération.
- **CA-21** : Étant donné une `feature/graph` locale sur un autre commit que `origin/feature/graph`, qu'elle la suive ou non, quand je fais le checkout de `origin/feature/graph` par n'importe quel geste, alors une confirmation affiche « feature/graph already exists locally. Reset it to origin/feature/graph? » et liste les commits de `feature/graph` absents de `origin/feature/graph` (SHA abrégé, résumé), sans rien modifier. « Reset and checkout » met `feature/graph` sur le commit de `origin/feature/graph` puis en fait le checkout ; « Checkout local as is » fait le checkout de `feature/graph` sans la déplacer ; Cancel ou Échap ne change rien.
- **CA-22** : Étant donné un checkout, une création, un Rename ou une suppression refusé par Git pour une autre raison (dont `origin` injoignable), alors un message d'une ligne s'affiche et « Details » montre la sortie brute de Git ; rien n'a changé.
- **CA-23** : Étant donné n'importe quel geste de cette spec terminé, alors HEAD pointe sur une branche (`git symbolic-ref HEAD` réussit), aucun commit n'est créé, et rien n'est poussé sauf par « Delete from origin ».
- **CA-24** : Étant donné une branche ou un commit qui a le focus, alors le `RefContextMenu`, le sélecteur de la `Toolbar`, le menu de choix de branche de `CommitDetail`, la saisie en ligne et les confirmations s'utilisent entièrement au clavier, avec un focus visible.

## Interface
- Écrans concernés (`ux.md`) : `History` (`ux/ecrans/history.md`, maquette `ux/maquettes/history.html`).
- Composants utilisés (`ux.md`) : `Toolbar` (sélecteur de branche, Branch ; `ux/ecrans/communs.md`), `BranchSidebar` (double-clic, saisie en ligne), `CommitGraph` / `RefLabel` (double-clic, saisie en ligne), `RefContextMenu` (Checkout, Rename, « Delete local », « Delete from origin », « Create branch here »), `CommitDetail` (Checkout, « Create branch here »), `ProfileBadge` (état non conforme, affiché seulement).
- Composants à ajouter : confirmations de « Delete local » (CA-15, CA-16) et de « Delete from origin » (CA-17), absentes de `ux/ecrans/dialogues.md` ; confirmation du checkout d'une `origin/…` dont la locale diffère (CA-21) ; menu de choix de branche de `CommitDetail` (CA-7) ; raison de « Delete local » désactivé (CA-13) ; messages de nom pris ou invalide (CA-10) ; message d'erreur avec Details (CA-22).
