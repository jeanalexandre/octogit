## Objectif
J'ouvre ou je clone un dépôt : il est rattaché au bon profil, par mon choix s'il existe, sinon par les règles. L'identité, la clé et la signature du profil sont écrites dans son `.git/config` local, pour qu'Octogit, le terminal, l'éditeur et les agents utilisent le même compte. Un réglage local fait à la main n'est jamais écrasé sans mon choix. Tant que l'identité du dépôt n'est pas conforme au profil, ou qu'un commit à pousser a un committer non conforme ou un auteur qui est un autre de mes profils, toute création de commit ou tout push est bloqué, sans contournement, et Octogit corrige en un geste.
- Jobs servis : J-12, J-13

## Critères d'acceptation
- **CA-1** : Étant donné les profils Pro (règle Path `~/Dev/**`) puis Client X (règle Remote owner `github.com/client-x/*`) dans cet ordre, et un dépôt `~/Dev/client-x/app` sans choix manuel dont `origin` est chez `client-x`, quand je l'ouvre, alors il est rattaché à Pro et `ProfileBadge` affiche Pro.
- **CA-2** : Étant donné une règle Remote owner `github.com/pro-company/*`, alors elle correspond à un `origin` `git@github.com:pro-company/app.git` comme à `https://github.com/pro-company/app.git` ; elle ne correspond pas à un dépôt dont seul un autre remote (ex. `upstream`) est chez `pro-company`, ni à un dépôt sans `origin`.
- **CA-3** : Étant donné un dépôt rattaché à Work sans identité locale, quand je l'ouvre, alors, sans dialogue, `git config --local user.name`, `user.email`, `core.sshCommand` et le réglage de signature renvoient dans le terminal les valeurs de Work ; `core.sshCommand` ne présente que la clé de Work ; les autres sections de `.git/config` (remotes, branches) sont inchangées.
- **CA-4** : Étant donné un `.git/config` local déjà conforme au profil, quand j'ouvre le dépôt, alors `.git/config` est identique octet pour octet et `ProfileBadge` est à l'état conforme.
- **CA-5** : Étant donné une seule des quatre valeurs locales (`user.name`, `user.email`, `core.sshCommand`, signature) différente de celle du profil Pro, quand j'ouvre le dépôt, alors `IdentityMismatch` s'affiche avant toute écriture : « Local Git config differs from profile Pro », chemin du dépôt, origine du rattachement (règle qui a désigné Pro, ou choix manuel), « Nothing has been written. », tableau profil / local des quatre valeurs, écarts mis en évidence autrement que par la couleur ; `.git/config` reste identique octet pour octet tant qu'aucun choix n'est fait.
- **CA-6** : Étant donné `IdentityMismatch`, quand je choisis « Overwrite with profile Pro », alors `.git/config` contient les valeurs de Pro (comme CA-3) et `ProfileBadge` passe à l'état conforme.
- **CA-7** : Étant donné `IdentityMismatch`, quand je choisis Cancel ou fais Échap, alors `.git/config` est identique octet pour octet, `ProfileBadge` est à l'état non conforme, création de commit et Push sont bloqués ; à la prochaine ouverture du dépôt, `IdentityMismatch` s'affiche de nouveau, y compris pour un dépôt laissé tel quel après Save d'un profil (`specs/configurer-les-profils.md`, CA-20).
- **CA-8** : Étant donné `IdentityMismatch`, quand je choisis « Import local config into Octogit… », alors `ProfileSettings` s'ouvre sur un nouveau profil pré-rempli avec les quatre valeurs locales ; `.git/config` est identique octet pour octet ; après Save, le dépôt est rattaché à ce profil, `ProfileBadge` est conforme, et ce rattachement est conservé aux ouvertures suivantes malgré les règles.
- **CA-9** : Étant donné `History`, quand je clique sur `ProfileBadge`, alors un menu liste les profils dans l'ordre de la liste, le profil actif coché, puis « Edit profiles… » et « Reset to rules » ; « Edit profiles… » ouvre `ProfileSettings` ; Cmd+, ouvre toujours `ProfileSettings` directement.
- **CA-10** : Étant donné le menu de `ProfileBadge`, quand je choisis Perso, alors le dépôt est rattaché à Perso et son `.git/config` reçoit les valeurs de Perso (comme CA-3), ou `IdentityMismatch` s'affiche si un réglage local différent existe (CA-5) ; après relance d'Octogit, le dépôt est toujours rattaché à Perso, même si une règle désigne un autre profil.
- **CA-11** : Étant donné un dépôt rattaché à la main à Perso alors que les règles désignent Pro, quand je choisis « Reset to rules », alors le choix est effacé, le dépôt est rattaché à Pro, et l'écriture suit CA-3 à CA-5 ; sans choix manuel, « Reset to rules » est désactivé.
- **CA-12** : Étant donné un dépôt cloné avec le profil Work choisi au clone, alors son `.git/config` contient les valeurs de Work (comme CA-3) avant l'affichage de `History`, et le dépôt reste rattaché à Work aux ouvertures suivantes, même si une règle désigne un autre profil.
- **CA-13** : Étant donné un dépôt sans choix manuel qu'aucune règle ne désigne, ou rattaché à un profil supprimé, alors `ProfileBadge` affiche « No profile — choose one », `.git/config` n'est pas écrit, création de commit et Push sont désactivés avec la raison « No profile ».
- **CA-14** : Étant donné un dépôt conforme au profil Work, alors `ProfileBadge` affiche le nom et la couleur de Work ; non conforme, il affiche le nom de Work et un signe d'alerte avec un texte, distinct de l'état conforme sans recours à la couleur seule.
- **CA-15** : Étant donné une valeur locale différente de celle de Work (ex. `user.email`), alors `WorkingChanges` affiche l'état bloqué : « Identity does not match profile Work. », puis, pour chaque valeur en écart, « Expected: <valeur de Work> » et « Found in .git/config: <valeur locale> », et « Fix repository identity » ; Commit est désactivé, Cmd+Entrée et Amend ne créent aucun commit (`git log` inchangé).
- **CA-16** : Étant donné un dépôt non conforme ou « No profile », quand je lance un merge, un cherry-pick, un revert, un rebase, un rebase interactif ou Continue dans `ConflictResolver`, alors l'action est refusée avec la même raison qu'en CA-15 ou CA-13 ; `git log`, les branches et l'index sont inchangés.
- **CA-17** : Étant donné un dépôt ouvert et conforme, quand je change une des quatre valeurs locales dans le terminal puis reviens dans Octogit, alors l'état bloqué (CA-15) s'affiche sans autre geste ; un Commit lancé à cet instant ne crée aucun commit.
- **CA-18** : Étant donné l'état bloqué, quand je clique sur « Fix repository identity », alors `.git/config` contient les valeurs de Work (comme CA-3), Commit redevient disponible et « Identity matches profile Work » s'affiche.
- **CA-19** (modifié le 07/11/2026) : Étant donné un dépôt non conforme ou « No profile », alors `PushButton` est à l'état bloqué avec la même raison ; aucun push ni Force push n'est possible et la branche distante ne change pas. « Delete from origin » est refusé avec la même raison que Push ; rien ne change sur `origin` (`specs/gerer-les-branches.md`, CA-19).
- **CA-20** : Étant donné le profil Work (`jag@work.fr`) et les profils Perso (`jag@perso.fr`) et Pro dans Octogit, alors un commit à pousser est fautif si son committer (nom ou adresse) diffère de Work, ou si son auteur a l'adresse d'un autre de mes profils ; un auteur qui n'est aucun de mes profils ne rend pas le commit fautif. Étant donné 2 commits à pousser dont 1 fautif, alors `PushButton` « Push 2 » est désactivé et affiche « 1 of 2 commits authored as jag@perso.fr. Profile Work expects jag@work.fr. » pour un auteur fautif, ou « 1 of 2 commits committed as <nom et adresse du committer>. Profile Work expects <nom et adresse de Work>. » pour un committer fautif, puis chaque commit à pousser (SHA abrégé, résumé) marqué « ✕ author », « ✕ committer » ou « ✓ ».
- **CA-21** : Étant donné un commit de collègue (auteur `alice@client.fr`, aucun de mes profils) repris par cherry-pick, avec un committer conforme à Work, alors il n'est pas fautif et ne bloque pas Push ; avec un committer non conforme, alors Push est bloqué (CA-20, « ✕ committer ») et « Fix commit identity » (CA-24) garde `alice@client.fr` en auteur.
- **CA-22** : Étant donné des commits d'autres auteurs déjà présents sur une branche distante (ex. `origin/develop` fusionnée dans ma branche), alors ils ne comptent pas parmi les commits à pousser et ne bloquent pas Push ; seuls les commits absents de toute branche distante du remote cible sont vérifiés.
- **CA-23** : Étant donné un commit à pousser fautif au sens de CA-20, alors son nœud dans `CommitGraph` porte une marque non conforme lisible sans la couleur, qui nomme le champ en cause (auteur ou committer) ; les autres commits, y compris ceux de collègues, à pousser ou déjà poussés, ne la portent pas.
- **CA-24** : Étant donné un ou plusieurs commits fautifs parmi les commits à pousser, quelle que soit leur position, alors `PushButton` propose « Fix commit identity » ; quand je clique, alors, en un seul geste, chaque commit fautif est réécrit avec Work comme committer, et avec Work comme auteur seulement si son auteur était un autre de mes profils, sinon avec son auteur d'origine (nom, adresse, date) ; les commits réécrits sont signés selon Work ; message et contenu de chaque commit sont inchangés ; aucun auteur d'origine n'est perdu.
- **CA-25** : Étant donné « Fix commit identity » terminé, alors les commits non fautifs gardent auteur, committer, message et contenu ; l'arbre de travail et l'index sont inchangés ; aucun commit déjà présent sur une branche distante n'est réécrit, et `PushButton` propose un push normal, jamais Force push ; Push redevient disponible. Étant donné des modifications non commitées qui empêchent la réécriture, quand je clique sur « Fix commit identity », alors elle est refusée avec un message, et la branche, l'index et l'arbre de travail ne changent pas.
- **CA-26** : Étant donné un commit créé au terminal avec `git -c user.email=jag@perso.fr commit` dans un dépôt Work, quand je reviens dans Octogit, alors Push est bloqué (CA-20) jusqu'à correction.
- **CA-27** : Étant donné une création de commit ou un Push bloqué, alors aucun menu, raccourci, réglage ni option ne permet de committer ou de pousser malgré le blocage.
- **CA-28** : Étant donné toute suite d'ouvertures, de clones, de choix dans `IdentityMismatch` ou dans le menu de `ProfileBadge`, et de corrections, alors `~/.gitconfig` est identique octet pour octet avant et après.
