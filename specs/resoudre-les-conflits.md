## Objectif
Un merge, un rebase, un Pull (rebase), un cherry-pick, un revert, un Pop ou un Apply s'arrête sur un conflit. `ConflictResolver` liste alors les fichiers par statut. Pour chaque fichier, je compose le résultat à partir de nous et eux, je l'édite, puis je le marque résolu. Continue termine l'opération, Abort la défait. Tant qu'elle dure, `OperationBanner` la rappelle sur tous les écrans, même si elle a été lancée depuis le terminal. Les actions qui la gêneraient sont désactivées. Je termine sans changer d'outil, et `git status` est propre.
- Jobs servis : J-9

## Périmètre
- **Inclus :** `ConflictResolver` : fichiers en trois groupes (Conflicted, Resolved, Auto-merged), `ConflictPane` nous / eux / résultat éditable, Take this block, Take all ours / theirs, navigation « Conflict i / n », Keep ours / Keep theirs / Delete pour un fichier non fusionnable, Open in external editor, Mark as resolved, Continue, Abort (confirmé si une résolution est faite), Back to graph (Échap). Conflits concernés : merge, rebase (dont interactif et Pull (rebase)), cherry-pick, revert (repris de `specs/integrer-une-branche.md` et de `specs/synchroniser.md`). Conflits d'un Pop ou d'un Apply, avec Done et Abort (repris de `specs/preparer-un-commit.md`). `OperationBanner` sur tous les écrans, y compris pour une opération lancée depuis le terminal (de `ux.md`, ligne « Pas de Welcome, clone, recherche, bandeau d'opération », et repris de `specs/explorer-l-historique.md`). Pendant l'opération, sont désactivés : le checkout, Branch, « Create branch here », Rename, « Delete local » et « Delete from origin » (repris de `specs/gerer-les-branches.md`), Stash, Pop, le merge, le rebase, le cherry-pick, le revert, le reset (Soft, Mixed, Hard ; repris de `specs/revenir-en-arriere.md`) et le Pull. Pendant un merge, Commit et Amend sont aussi désactivés. Échec de Continue avec le message brut de Git.
- **Exclu :**
  - Annulation (Undo) après Continue, Done ou Abort (non-objectif).
  - Lancement du merge et du rebase → `specs/integrer-une-branche.md` ; lancement du Pull (rebase) → `specs/synchroniser.md` ; lancement du Pop et de l'Apply, et Drop → `specs/preparer-un-commit.md`.
  - Refus de Continue pour identité non conforme ou « No profile » → `specs/proteger-l-identite.md` (CA-16).
  - Force push après un rebase terminé → `specs/synchroniser.md` (CA-16).
  - Rebase interactif (`InteractiveRebase`, J-7) → `specs/nettoyer-une-branche.md` ; seuls ses conflits relèvent de cette spec
  - Actions du `RefContextMenu` et de `CommitDetail` (cherry-pick, revert, reset) → `specs/revenir-en-arriere.md` ; seuls les conflits du cherry-pick et du revert relèvent de cette spec

## Critères d'acceptation
- **CA-1** : Étant donné un merge, un rebase, un cherry-pick ou un revert lancé dans Octogit qui s'arrête sur un conflit, alors `ConflictResolver` s'ouvre. Ses fichiers sont groupés en « Conflicted · n », « Resolved · n » et « Auto-merged · n ». Chaque fichier porte un statut lisible sans la couleur (`!`, `✓`, `·`). Les fichiers listés sont ceux que `git status` donne en conflit ou fusionnés.
- **CA-2** : Étant donné un fichier texte en conflit sélectionné, alors `ConflictPane` affiche Ours et Theirs, puis Result. Ours et Theirs portent chacun leur branche et leur SHA abrégé (ex. « feature/profiles · a3f9c21 », « develop · e92a6b3 ») et sont teintés de leur lane. « Conflict i / n » et ses flèches passent d'un bloc en conflit au bloc suivant ou précédent.
- **CA-3** : Étant donné un bloc en conflit, quand je coche Take this block côté Ours, côté Theirs ou des deux côtés, alors Result contient ce ou ces blocs à la place du marqueur, dans l'ordre Ours puis Theirs. Take all ours et Take all theirs font de même pour tous les blocs du fichier. Result reste éditable au clavier.
- **CA-4** : Étant donné un Result qui contient encore une ligne de marqueur de conflit (`<<<<<<<`, `=======` ou `>>>>>>>`), alors Mark as resolved est désactivé, et le décompte le dit (« Block 1 resolved · Block 2 to do »). Sans marqueur, Mark as resolved est actif.
- **CA-5** : Étant donné un clic sur Mark as resolved, alors le contenu de Result est écrit dans le fichier, octet pour octet, puis indexé : `git diff --cached` le montre et `git status` ne le liste plus en conflit. Le fichier passe dans Resolved et le fichier en conflit suivant s'affiche.
- **CA-6** : Étant donné un clic sur Open in external editor, alors le fichier s'ouvre dans l'application par défaut de macOS pour son type ; Octogit n'a aucun réglage d'éditeur. Quand j'enregistre le fichier puis reviens dans Octogit, alors Result affiche son nouveau contenu. Étant donné un fichier résolu au terminal (`git add`), alors il passe dans Resolved sans autre geste.
- **CA-7** : Étant donné au moins un fichier dans Conflicted, alors Continue est désactivé. Quand le dernier fichier passe dans Resolved, alors Continue devient actif et l'écran affiche « ✓ n resolved · m auto-merged ».
- **CA-8** : Étant donné un merge en conflit où tout est résolu, quand je clique sur « Continue merge », alors le commit de merge est créé avec le message par défaut de Git (`specs/integrer-une-branche.md`, CA-6) et l'identité du profil (CA-8 de la même spec). `OperationBanner` disparaît et `History` s'affiche. Dans le terminal, `git status` n'indique aucune opération en cours.
- **CA-9** : Étant donné un rebase de 5 commits arrêté à l'étape 2, où tout est résolu, quand je clique sur Continue, alors le commit 2 est rejoué avec son message et son auteur d'origine, et le rebase reprend. S'il s'arrête de nouveau sur un conflit, alors `ConflictResolver` affiche les nouveaux fichiers et `OperationBanner` affiche l'étape en cours (« 3 / 5 »). Sinon, le rebase se termine comme en CA-8, sans opération en cours.
- **CA-10** : Étant donné un cherry-pick ou un revert en conflit où tout est résolu, quand je clique sur Continue, alors le commit est créé avec le message que Git propose, et l'opération se termine comme en CA-8.
- **CA-11** : Étant donné une opération en conflit, quand je confirme Abort, alors l'opération est abandonnée. La branche courante, l'index et l'arbre de travail reviennent à leur état d'avant l'opération. Pour un Pull (rebase), la branche pointe sur son commit d'avant le pull. `OperationBanner` disparaît, et `git status` n'indique aucune opération en cours.
- **CA-12** : Étant donné Continue refusé par Git (ex. « error: Committing is not possible because you have unmerged files. »), alors trois éléments s'affichent : « Continue failed. », la sortie brute de Git, et « Repository left as is. Resolve, then Continue again. ». L'opération reste en cours. Les branches, l'index et l'arbre de travail ne changent pas.
- **CA-13** : Étant donné une opération en cours, alors `OperationBanner` est visible sur `History`, `DiffView`, `ConflictResolver` et `ProfileSettings`. Il nomme l'opération et ses branches (« Merge in progress · develop into feature/profiles ») et le nombre de fichiers restants (« 1 file left »). Pour un rebase, il nomme aussi l'étape (« 2 / 5 »). Il propose Abort et Continue (actif selon CA-7). Hors de `ConflictResolver`, il propose aussi Resolve.
- **CA-14** : Étant donné `ConflictResolver`, quand je fais Échap ou clique sur Back to graph, alors `History` s'affiche, `OperationBanner` reste, et l'opération reste en cours. Quand je clique sur Resolve dans `OperationBanner`, alors `ConflictResolver` revient avec les résolutions déjà marquées.
- **CA-15** : Étant donné un merge, un rebase, un cherry-pick ou un revert lancé depuis le terminal et en cours, quand j'ouvre le dépôt ou reviens dans Octogit, alors `OperationBanner` l'affiche sans autre geste. Étant donné cette opération terminée ou abandonnée au terminal, alors `OperationBanner` disparaît au retour dans Octogit.
- **CA-16** (modifié le 07/11/2026) : Étant donné une opération en cours, alors sont désactivés : le checkout d'une branche, Branch, « Create branch here », Rename, « Delete local » et « Delete from origin » (raison « Operation in progress. », `specs/gerer-les-branches.md`, CA-20), Stash, Pop, les entrées merge, rebase, rebase interactif, cherry-pick et revert, les entrées Soft, Mixed et Hard du reset (raison « Operation in progress. », `specs/revenir-en-arriere.md`, CA-21), et le Pull. Aucun raccourci ne les lance. Ils redeviennent actifs à la fin de l'opération.
- **CA-17** : Étant donné un Pop ou un Apply en conflit, alors `ConflictResolver` s'ouvre sur les fichiers en conflit, et `OperationBanner` affiche sa variante conflit avec Abort et Done à la place de Continue. Le stash reste dans `git stash list` (`specs/preparer-un-commit.md`, CA-21). Done est désactivé tant qu'un fichier est dans Conflicted. Quand je clique sur Done, alors les fichiers résolus sont désindexés, comme après un Pop sans conflit. `OperationBanner` disparaît et le stash reste dans la liste. Quand je confirme Abort, alors les fichiers touchés reviennent à leur état d'avant le Pop ou l'Apply, et le stash reste dans la liste.
- **CA-18** : Étant donné `ConflictResolver`, alors ces actions se font au clavier, avec un focus visible : sélection d'un fichier, Take this block, navigation entre blocs, Keep ours / Keep theirs / Delete, Mark as resolved, Continue ou Done, Abort, Back to graph.
- **CA-19** : Étant donné au moins un fichier marqué résolu, quand je clique sur Abort, alors une confirmation nomme ce qui sera perdu (ex. « Abort rebase? 2 resolved files will be lost. »). Après annulation, rien ne change. Étant donné aucun fichier encore résolu, alors Abort agit sans confirmation.
- **CA-20** : Étant donné un fichier en conflit non fusionnable, alors `ConflictPane` ne propose pas de Result éditable. Sont non fusionnables : un fichier binaire, un fichier supprimé d'un côté et modifié de l'autre, un fichier renommé. Les choix proposés portent sur le fichier entier : Keep ours, Keep theirs, et Delete seulement si un côté l'a supprimé. Quand je choisis l'un d'eux, alors le fichier est écrit ou supprimé selon ce choix. Ce résultat est indexé, et le fichier passe dans Resolved.
- **CA-21** : Étant donné un merge en cours, alors Commit et Amend de `WorkingChanges` sont désactivés avec la raison « Merge in progress ». Cmd+Entrée ne crée aucun commit. Seul Continue termine le merge (CA-8).

## Interface
- Écrans concernés (`ux.md`) : `ConflictResolver` (`ux/ecrans/conflict-resolver.md`, maquette `ux/maquettes/conflict-resolver.html` : « Conflicts remaining », « All resolved », « Git refuses », « Back on the graph ») ; `History` (maquette `ux/maquettes/history.html`, « Operation in progress (all screens) ») ; `DiffView` et `ProfileSettings` (bandeau seulement).
- Composants utilisés (`ux.md`) : `ConflictPane` (à résoudre · résolu), `OperationBanner` (merge · rebase · cherry-pick · revert · conflit), `Toolbar` (opération en cours), `WorkingChanges` (Commit désactivé), `ProfileBadge` (affiché).
- Composants à ajouter : décompte des blocs dans Result ; variante non fusionnable de `ConflictPane` (Keep ours, Keep theirs, Delete) ; confirmation d'Abort ; Done pour un conflit de Pop ou d'Apply ; message d'échec de Continue ; raison « Merge in progress » dans `WorkingChanges` ; états désactivés de Branch, Stash, Pop, du checkout, de « Create branch here », Rename, « Delete local », « Delete from origin » et des entrées cherry-pick, revert et reset (Soft, Mixed, Hard).

## À reporter
- Vers `stack.md` : il faut pouvoir :
  - détecter une opération en cours et son étape (merge, rebase, cherry-pick, revert, conflit de stash), y compris lancée au terminal ;
  - lire les versions nous, eux et base d'un fichier en conflit, et reconnaître un conflit non fusionnable (binaire, suppression d'un côté, renommage) ;
  - écrire ou supprimer un fichier résolu, puis l'indexer ;
  - désindexer les fichiers après un conflit de stash, ou les remettre dans leur état d'avant le Pop ou l'Apply ;
  - continuer et abandonner chaque opération ;
  - ouvrir un fichier dans l'application par défaut de macOS et détecter son enregistrement ;
  - conserver la sortie brute de Git.
- Vers `ux.md` :
  - Libellés du bandeau : `history.html` montre « Resume · Continue · Abort », et `conflict-resolver.html` montre « Resolve · Abort ». Cette spec retient Resolve, Continue et Abort (CA-13).
  - J-9 ne désactive que le checkout, le merge, le rebase et le Pull. La maquette désactive aussi Branch, Stash et Pop. Cette spec ajoute le rebase interactif, le cherry-pick, le revert, le reset, « Create branch here », Rename, « Delete local » et « Delete from origin » (CA-16), ainsi que Commit et Amend pendant un merge (« Merge in progress », CA-21).
  - Ouverture de `ConflictResolver` : automatique pour une opération lancée dans Octogit, par Resolve pour une opération trouvée au terminal (CA-1, CA-15).
  - Conflit d'un Pop ou d'un Apply : Done et Abort, sans maquette ni libellé du bandeau (CA-17).
  - Confirmation d'Abort quand une résolution est faite (CA-19) : absente des maquettes, qui montrent un Abort immédiat.
  - Variante non fusionnable de `ConflictPane` (Keep ours, Keep theirs, Delete) : absente (CA-20).
  - Open in external editor ouvre l'application par défaut de macOS ; Octogit n'a pas de réglage d'éditeur (CA-6).
