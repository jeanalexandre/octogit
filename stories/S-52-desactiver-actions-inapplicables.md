# Story S-52 : Désactiver ou refuser les actions inapplicables : HEAD détachée, commit racine, plage avec merge, commit de merge, cherry-pick vide

## Objectif
Sur un dépôt en HEAD détachée, un commit racine, un commit de merge ou une plage qui contient un merge, les actions qui ne peuvent pas s'appliquer sont désactivées avec leur raison (ou refusées avec un message qui nomme le merge), et un cherry-pick sans changement rend « <sha7> brings no changes to <branche>. », le tout sans rien modifier dans le dépôt.

## Critères d'acceptation
- **nettoyer-une-branche CA-2** : Étant donné un commit qui n'est ni ancêtre ni sommet de la branche courante, alors l'entrée « Interactive rebase from here » est désactivée. Étant donné un dépôt en HEAD détachée, alors l'entrée est désactivée pour tout commit, avec la raison « No current branch. ». Étant donné le commit racine (sans parent), alors l'entrée est désactivée avec la raison « Root commit cannot be rebased. ». Dans ces trois cas, aucun raccourci ne lance le rebase interactif.
- **nettoyer-une-branche CA-3** : Étant donné une plage (C et les commits suivants) qui contient un commit de merge, quand je choisis « Interactive rebase from here », alors le rebase interactif est refusé avec un message qui nomme le merge par son SHA abrégé (ex. « Range contains a merge commit (c41d8e0). Choose a later starting commit. ») ; `git log`, les branches, l'index et l'arbre de travail sont inchangés, et aucun rebase n'est en cours.
- **revenir-en-arriere CA-6** (modifié le 07/11/2026) : Étant donné le commit `c41d8e0` dont les changements sont déjà tous présents sur `feature/profiles` courante, quand je choisis Cherry-pick, alors le message « c41d8e0 brings no changes to feature/profiles. » s'affiche ; aucun commit n'est créé, aucune opération ne reste en cours (`git status`), branches, index et arbre de travail ne changent pas.
- **revenir-en-arriere CA-9** : Étant donné un dépôt en HEAD détachée, alors Cherry-pick, Revert et le sous-menu Reset sont désactivés avec la raison « No current branch. », dans le menu comme dans `CommitDetail` ; aucun raccourci ne les lance.
- **revenir-en-arriere CA-20** : Étant donné un commit de merge, alors Cherry-pick et Revert sont désactivés avec la raison « Merge commits cannot be cherry-picked or reverted. », dans le menu comme dans `CommitDetail` ; aucun raccourci ne les lance ; le sous-menu Reset reste disponible.

## Contexte technique
- Dépend de S-50 (pas livrée à la rédaction) : relire `stories/S-50-gestes-bloques-pendant-une-operation.md` et le code livré avant de coder. S-50 ajoute `operationBlocked`, la raison d'identité partagée et les `Entry.disabled` de `RefContextMenu`, les boutons de `CommitDetail` et le garde « Operation in progress. » du cœur. Ici, prolonger ces mêmes endroits, sans les dupliquer. Ordre des raisons quand plusieurs s'appliquent (choix de présentation de la fiche) : « Operation in progress. » (S-50), puis la raison de cette story, puis l'identité.
- Rebase interactif, état actuel : `src/lib/components/RefContextMenu.svelte` (`hasInteractiveRebase` l. ~290) n'affiche l'entrée « Interactive rebase from here » que sur un commit de la branche courante et sans branche courante elle est absente ; `src/App.svelte` (`menuPlan`, `readMenuPlan` l. ~1405, `menuOnCurrentBranch`, `openInteractiveRebase`) lit la plage à l'ouverture du menu par `commands.readRebasePlan` ; une erreur (« No current branch. », « Root commit cannot be rebased. », « The commit is not on the current branch. ») laisse l'entrée absente. Il faut qu'elle reste affichée et désactivée : raison « No current branch. » ou « Root commit cannot be rebased. » ; commit hors de la branche : désactivée sans raison affichée (la spec n'en fixe pas). Les trois cas viennent de `crates/git/src/rebase_plan.rs` (`read_rebase_plan`, messages déjà exacts) : l'interface distingue les causes sans comparer du texte libre si possible (au choix de dev : champ ou énumération dans `RebasePlanView`, `src-tauri/src/rebase_plan.rs` l. ~106 ; `pnpm gen:bindings` si le contrat change). Entrée désactivée : `aria-disabled`, ni clic ni Entrée ne la lancent.
- Plage avec merge (CA-3) : `read_rebase_plan` suit le premier parent et ne voit pas les merges. Ajouter la détection d'un commit à plusieurs parents dans la plage (du commit choisi au sommet, choisi compris) ; l'entrée reste active et le refus se produit au choix de l'entrée : message « Range contains a merge commit (<sha7>). Choose a later starting commit. » en une ligne près de l'en-tête (patron `checkoutNotice` de `App.svelte`), `InteractiveRebase` ne s'ouvre pas. Nommer le merge le plus proche du sommet (c'est celui qu'il faut dépasser pour choisir un commit valide). Refus aussi côté cœur : `start_interactive_rebase` (`src-tauri/src/commands.rs` l. ~436, `crates/git/src/interactive_rebase.rs`) refuse HEAD détachée, commit racine et plage avec merge avant tout sous-processus Git (le refus ne dépend jamais de l'interface). Aucun rebase en cours, `git log`, branches, index, arbre inchangés. Pour information (S-42, revue 1) : `read_rebase_plan` relit la plage à chaque ouverture du menu ; la détection de merge ne doit pas ajouter de seconde passe (un seul parcours), aucun seuil chiffré.
- HEAD détachée : `RefContextMenu.svelte` : entrées Cherry-pick et Revert (`pick`, l. ~189) et sous-menu Reset (`hasReset`, qui exige `currentBranch !== null`, titre « Reset <branche> to here › ») doivent rester affichés et désactivés avec « No current branch. » quand `currentBranch` est `null` (menus d'un commit et d'une `origin/…`). Le titre du sous-menu sans nom de branche est au choix de dev (« Reset to here › »). `CommitDetail.svelte` (boutons Cherry-pick et Revert, l. ~229) : désactivés avec la même raison, lue de ce que `History.svelte` lui passe (nouvelle propriété ; `History.svelte` l. ~935 passe déjà `oncherrypick` et `onrevert`). Côté cœur, avant tout sous-processus Git : `cherry_pick_checked`, `revert_checked`, `reset_branch` et `reset_hard` (`src-tauri/src/working_tree.rs`) refusent « No current branch. » ; garde à côté de `ensure_conform`, ou fonction du crate `git` lisant `head_name` (`gix`, voir `read_rebase_plan`). Reset : aucun raccourci, ni clic ni Entrée ne l'ouvrent ; `ResetHardDialog` ne peut pas s'ouvrir (`preview_reset_hard` inchangée, lecture seule).
- Commit de merge (CA-20) : `CommitDetail.svelte` connaît déjà `isMerge` (`detail.parents.length > 1`, l. 112) ; désactiver Cherry-pick et Revert avec « Merge commits cannot be cherry-picked or reverted. ». Dans `RefContextMenu`, le menu d'un commit (`menu.kind === "commit"`) et celui d'une `origin/…` (le commit vers lequel elle pointe, voir `pickFromMenu`, `App.svelte` l. ~1272) : le parent passe à `RefContextMenu` un booléen « le commit visé est un merge », lu des `parents` des lignes du graphe (`CommitInfo.parents`, `crates/git/src/lib.rs` l. 89) sans nouvelle lecture.
