# Story S-54 : Dépôt introuvable (Locate…, Remove from recent, rattachement manuel conservé) et clone refusé ou vers un dossier non vide

## Objectif
Un dépôt mémorisé qui a disparu du disque s'affiche en état « Repository not found: <chemin> » avec Locate… (le rattachement manuel suit le dépôt) et Remove from recent ; un clone refusé affiche « Clone failed: » avec Copy public key et Try again, et un dossier de destination non vide est refusé, dans les deux cas sans rien changer sur le disque.

## Critères d'acceptation
- **demarrer-un-depot CA-6** : Étant donné le dernier dépôt ouvert déplacé ou supprimé, quand je lance Octogit, alors `Welcome` affiche « Repository not found: » suivi de son chemin, avec Locate… et Remove from recent ; le même état s'affiche quand je clique sur un dépôt récent introuvable.
- **demarrer-un-depot CA-7** : Étant donné l'état « dépôt introuvable », quand je choisis Locate… puis le dossier où le dépôt a été déplacé, alors il s'ouvre dans `History` et son entrée de Recent porte le nouveau chemin ; quand je choisis Remove from recent, alors l'entrée disparaît de Recent et ne revient pas au relancement, et aucun fichier n'est supprimé sur le disque.
- **demarrer-un-depot CA-13** : Étant donné un clone refusé (ex. clé absente de GitHub), alors « Clone failed: » suivi du message brut de Git ou de SSH s'affiche, avec Copy public key (clé du profil choisi) et Try again ; Try again relance avec le même profil, la même URL et le même dossier ; le dossier de destination revient à son état d'avant.
- **demarrer-un-depot CA-14** : Étant donné un dossier de destination qui existe et n'est pas vide, quand je clique sur Clone, alors le clone est refusé avec un message qui nomme ce dossier, et son contenu est identique avant et après.
- **demarrer-un-depot CA-19** : Étant donné un dépôt rattaché à la main à Perso alors que les règles désignent Pro, déplacé puis retrouvé par Locate…, alors il reste rattaché à Perso à son nouveau chemin, `ProfileBadge` affiche Perso, et ce rattachement est conservé au relancement ; les règles ne sont pas réappliquées.
- **Reporté depuis S-12 (revue 1)** : le `ProfileBadge` d'un récent introuvable (correspondant à une règle de chemin) n'affiche pas « ⚠ … identity mismatch » : la lecture de son `.git/config` échoue, ce n'est pas un écart d'identité.

Nouveau cas de contrat (`tauri-specta`, `pnpm gen:bindings`) : par exemple une variante `LaunchState` et une variante `OpenError` portant le chemin ; forme au choix de `dev`, mais « dossier non Git » (CA-4) garde son message nommant le dossier. `src/App.svelte` est un gros fichier : `git grep -n`, puis Read en offset et limit (`recent`, `error`, `open`, `chooseFolder`, `show`, `cloneRepository`, `cloneDialog`, `onMount` ~ligne 1745).
- Remove from recent : nouvelle fonction du `store` (`crates/store/src/lib.rs`, gros fichier : `git grep -n`) qui retire l'entrée de `recent` ; elle ne touche aucun fichier du disque. Elle garde le rattachement manuel mémorisé du chemin (rien dans la spec ne dit de l'effacer ; décision de `dev` à signaler si un test l'exige). L'entrée ne revient pas au relancement (`last_repository` = tête de la liste : le récent suivant s'ouvre alors normalement). Après Remove from recent, `Welcome` s'affiche à l'état normal (récents restants, `error` vidé).
- Locate… : sélecteur de dossier existant (`commands.chooseFolder`, `window.__octogitChosenFolder` dans `src/web-bridge.ts`). Nouvelle fonction du `store` qui transfère de l'ancien chemin vers le nouveau : entrée de Recent (date gardée ou mise à jour par l'ouverture), rattachement manuel (`manual_profiles`), états par dépôt (`collapsed_folders`, `graph_widths`) ; un nouveau chemin déjà présent dans Recent est fusionné, jamais dupliqué. Puis ouverture par `open::open_repository_in` (qui appelle `attach_profile`, lit le choix manuel : CA-19, les règles ne sont pas réappliquées, rien n'est écrit dans `.git/config` d'un dépôt déjà conforme). Dossier choisi non Git : message nommant ce dossier, état « introuvable » conservé, rien d'écrit dans le dossier ni dans le `store`. Pas de nouvelle version de fichier attendue (aucune clé ajoutée) ; sinon version + migration + fichier d'exemple dans `store`.
- Badge d'un récent introuvable : `badge_of` (`src-tauri/src/attach.rs` ~ligne 379) lit le `.git/config` local ; sur un chemin absent la lecture échoue et rend `conform = false` (« ⚠ identity mismatch »). Pour un chemin absent, le badge garde le profil (manuel mémorisé, sinon règles de chemin) et n'affiche pas le signe d'écart (`conform = true` par convention : rien à comparer). `ProfileBadge` n'est pas modifié sauf nécessité (`src/lib/components/ProfileBadge.svelte`). Ne pas modifier `attach_profile`, `resolve`, `compare_for_attach`.
- Clone refusé (CA-13) : `CloneDialog` affiche déjà « Clone failed: » + sortie brute (`src/lib/components/CloneDialog.svelte`, `error`) ; ajouter Copy public key (clé du profil choisi : `commands.copyPublicKey(profile.sshKeyPath)`, `copy_public_key` de `commands.rs` ligne ~1362, `window.__octogitClipboard` sous le pont de test) et Try again (relance `onclone` avec le même profil, la même URL, le même dossier, sans ressaisie ; icône Lucide devant chaque bouton). Retour du dossier à son état d'avant sur refus : `crates/git/src/clone.rs` (`Destination::before` / `restore`) n'est appelé aujourd'hui qu'à l'annulation et au délai ; l'appeler aussi quand `git clone` échoue (`CloneError::Failed`), car `git` laisse les dossiers parents qu'il a créés (destination absente et parents absents : retirés ; destination vide préexistante : vidée, conservée ; destination non vide : jamais touchée).
